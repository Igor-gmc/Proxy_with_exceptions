# ProxyBridge

Windows-приложение для подключения через HTTP CONNECT или SOCKS5-прокси
с исключениями для отдельных программ. Использует sing-box, виртуальный
адаптер Wintun и собственный модуль Windows Filtering Platform (WFP).

Версия: **0.3.05**, кандидат после рефакторинга. Windows 10/11 x64;
для работы нужны права администратора.

## Возможности

- Перенаправление TCP через настроенный пользователем прокси.
- Исключения по полному пути EXE: выбранные приложения получают прямой доступ.
- KillSwitch и отдельные действия для остановки с блокировкой и возврата интернета.
- Автозапуск при входе в Windows, сворачивание в трей, проверка скорости.
- Локальные журналы подключения и активности, диагностика TCP и WFP.
- Тёмный интерфейс с разделами «Обзор», «Прокси», «Исключения» и «Справка».

Встроенных адресов, логинов и паролей прокси нет. При первом запуске открывается
форма настройки; подключения до ввода параметров не происходит. Программа
поддерживает IPv4-адрес прокси, а не доменное имя. SOCKS5 используется для TCP;
неподдерживаемый UDP не должен обходить защиту.

## Первый запуск

1. Соберите приложение по инструкции ниже и запустите `ProxyBridge-0.3.05.exe`.
2. На странице «Прокси» введите адрес, порт, протокол и, если нужны, логин и пароль.
3. Нажмите «Сохранить / применить», затем «Подключить».
4. Дождитесь успешной проверки на странице «Обзор».
5. При необходимости добавьте EXE в «Исключения» и примените изменения.

После сохранения корректного профиля последующие обычные запуски автоматически
пытаются подключиться. Крестик скрывает окно в трей. «Остановить и блокировать»
сохраняет защиту; «Отключить и вернуть интернет» снимает собственную блокировку.
Выход с сохранением KillSwitch также оставляет блокировку. Если приложение
закрыто, `Recover-Internet.cmd` запускает явное восстановление с запросом UAC.

Исключения намеренно разрешают прямой доступ, в том числе при остановленном
прокси. При ручной остановке с исключениями может разрешаться общий системный
DNS к серверам активных адаптеров. Подробнее — [HELP.txt](HELP.txt).

## Статус сетевой защиты

Проект находится в разработке. Полная проверка отсутствия утечек при авариях,
для уже открытых соединений, IPv6, DNS/UDP и сочетаний со сторонними VPN и
антивирусами не завершена. Успешная сборка или HTTPS-проверка не подтверждает
все эти сценарии. Ошибка подключения не должна автоматически снимать защиту.

## Сборка из исходников

Понадобятся Windows x64, .NET SDK 10, Visual Studio Build Tools с компонентами
Desktop development with C++ и Windows SDK, PowerShell 5.1 или новее. Git нужен
для клонирования; доступ в интернет — для получения зависимостей и NuGet.

```powershell
git clone git@github.com:Igor-gmc/Proxy_with_exceptions.git
cd Proxy_with_exceptions
powershell -NoProfile -ExecutionPolicy Bypass -File tools/Restore-Dependencies.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1
```

Восстановление зависимостей загружает закреплённые архивы sing-box и Wintun
из официальных источников и проверяет SHA-256 до распаковки. Сборка компилирует
нативный модуль, создаёт архив компонентов из явного списка файлов и выпускает
единый EXE с .NET runtime. Прокси-профили и файлы окружения в пакет не включаются.
`build.ps1 -BuildOnly` оставляет результат только в `release/`.

Основной EXE и сценарий восстановления появляются в корне; копии и SHA-256 —
в `release/versions/`. Бинарники, зависимости и промежуточные файлы не хранятся
в Git. Номер выпуска задаётся в [Version.props](Version.props).

## Тесты

```powershell
dotnet run --project tests/Core.Tests -c Release
dotnet run --project tests/Settings.Tests -c Release
dotnet run --project tests/Logging.Tests -c Release
dotnet run --project tests/Diagnostics.Tests -c Release
```

Выполняйте после сборки, чтобы был создан пакет ресурсов. Эти проверки
используют синтетические данные и не поднимают рабочий туннель. Остальные
проверки и ограничения описаны в [tests/README.md](tests/README.md).
Интеграционные проверки могут менять сетевое состояние: они вынесены в
[отдельный стенд](integration/README.md) и не запускаются сборкой.

Тестовые сценарии не входят в рабочий EXE. Для bundle/self/UI-проверок соберите
отдельный хост командой `powershell -File build.ps1 -BuildOnly -IncludeTests`.
Команды `--self-test`, `--ui-test` и `--bundle-test` принимаются только этим
хостом. Рабочий EXE отклоняет их до запуска приложения. Его пользовательские
режимы — без аргументов, `--startup` или `--recover`; смешанные и неизвестные
аргументы также отклоняются.

## Данные и конфиденциальность

Настройки сохраняются локально с Windows DPAPI, журналы — в
`%LOCALAPPDATA%\ProxyBridge`. Компоненты извлекаются в защищённый каталог
`%ProgramFiles%\ProxyBridgeComponents`. Журналы могут содержать сетевые адреса
и пути приложений, поэтому не прикладывайте их к публичным issue без очистки.

`.env` не требуется. Репозиторий исключает файлы окружения, ключи, VPN-профили,
настройки, журналы и результаты локальных расследований. Перед коммитом
выполняйте `python tools/check-publication.py --staged` и просматривайте изменения.
Подробнее — [SECURITY.md](SECURITY.md).
